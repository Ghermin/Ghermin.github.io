# Bored Dev Playground

La vitrine de tous les projets (https://ghermin.github.io/). Les projets sont dans les dossiers voisins (`../autowash`, `../camtel`…) et leurs pages GitHub suivent le kit `kit/playground.css`.

- **Modifier le kit** (`kit/playground.css`) touche toutes les pages des projets : vérifier que ça reste bon sur chacune, puis lancer `sh kit/sync.sh` et commiter dans chaque projet (Blind Test : `npm run pages` en plus ; La Quittance et Mots fléchés : augmenter `CACHE` dans `sw.js`).
- **Ajouter un projet** : une carte `<li class="card" data-p="…">` dans `index.html` (`data-p` = ses filtres parmi `windows android web jeux`), son icône dans `brand/icons/` (générée ensuite dans `assets/projects/`), mettre à jour les compteurs « N résultats » (total et par filtre), ajouter sa page dans `sitemap.xml` et sa copie du kit dans `kit/sync.sh`, refaire l'image de partage (`node build.js --og` dans `brand/`) et celle du repo (`node build.js --social <id>`, accroche dans `TAGLINES`, à envoyer à la main dans Settings du repo), ajouter sa case dans le README de profil (`../Ghermin`), donner au repo ses topics (dont `bored-dev-playground`), une licence et le lien de sa page en « Website », et donner à sa page le bandeau `pg-strip` et un `CLAUDE.md` comme les autres projets. L'appli elle-même (web, Android, Windows) porte un lien discret « un projet du bored dev playground » vers https://ghermin.github.io/ en pied de page (`pg-sig` du kit pour les pages web). `node tools/check.mjs` vérifie tout ça (la CI aussi, à chaque push et chaque lundi).
- **Badges** « nouveau » / « mis à jour » : `<p class="badge"><time datetime="AAAA-MM-JJ">…</time></p>` sous l'icône de la carte, à retirer au bout de 30 jours (la CI échoue sinon).
- `404.html` est servie pour les adresses inconnues hors des projets, à n'importe quelle profondeur (`/xyz/abc`) : chemins absolus seulement. Sous un projet (`/jus/xyz`), GitHub sert la 404 du repo du projet, ou la sienne s'il n'en a pas.
- **Icônes** : une par projet dans `brand/icons/`, même grille et même style (voir le README). Après une modification, `node build.js <id>` dans `brand/` régénère favicons, icônes Android et Windows dans le projet, puis commiter dans les deux repos. Un nouveau projet a besoin de son SVG et d'une entrée dans `TARGETS` de `brand/build.js`.
- Toutes les pages : thème clair / sombre automatique, responsive, les 2 polices du playground et aucune autre (Bricolage Grotesque via `--pg-font` du kit, JetBrains Mono via `--pg-mono`), les couleurs du dégradé de son icône (`--pg-accent` / `--pg-accent-2`) sans autre couleur décorative.
- **Infos perso** : seule identité publique autorisée, Ghermin. Rien d'autre dans les pages, cartes, icônes ni commits.
- **Captures d'écran** (pages des projets, cartes) : les regarder en entier avant de les publier. Retirer noms et pseudos, overlays (Steam, Discord, notifications), autres fenêtres, barre des tâches, chemins `C:\Users\...`, second écran ; recadrer, flouter fort, réenregistrer sans métadonnées.
